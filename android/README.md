# Sketch3D — Android shell (Rust / wry / tao / Gradle)

Native Android wrapper for the Sketch3D web app. The 3D application is still
the single-file web build (`../index.html`, Three.js r128); this project only
provides the native container:

```
┌─────────────────────────────────────────────┐
│ Android app (com.notebysebas.sketch3d)      │
│                                             │
│  MainActivity.kt ──extends──> WryActivity   │  ← generated by wry's build.rs
│        │                                    │
│        └── Rust (libsketch3d.so)            │  ← tao event loop + wry WebView
│                 │                           │
│                 └── WebViewAssetLoader      │  ← serves ../assets/ over
│                       https://app.assets    │     a stable https origin
│                                             │
│  Exporter.kt  ← window.AndroidBridge       │  ← saves GLB/OBJ/USD… to
│                     (Kotlin JS interface)   │     the device Downloads
└─────────────────────────────────────────────┘
```

## Requirements

| Tool | Version used here |
|---|---|
| Rust | 1.98 with `aarch64-linux-android`, `armv7-linux-androideabi`, `x86_64-linux-android` |
| cargo-ndk | 4.x (`cargo install cargo-ndk`) |
| Android SDK | platform 35, build-tools 35, NDK 26/27 |
| JDK | 17 |
| Gradle | 8.9 (via the wrapper, no local install needed) |

`ANDROID_HOME` must point at the SDK (or pass `-AndroidSdk`).

## Build

```powershell
# release APK for the three main ABIs
.\build-apk.ps1

# fast iteration on an x86_64 emulator
.\build-apk.ps1 -BuildType debug -Abis x86_64 -Install

# rebuild only the APK payload / only the Rust lib
.\build-apk.ps1 -SkipRust
.\build-apk.ps1 -SkipAssets
```

The script does three things:

1. **Assets** — copies `../index.html` into `app/src/main/assets/`, rewrites the
   CDN `<script>`/font `<link>` to local files, disables the service worker,
   downloads `three.min.js` r128 + the DM Mono woff2 files and copies the PWA
   icons. The result is a fully offline app.
2. **Rust** — `cargo ndk -t <abis> -P 24 -o app/src/main/jniLibs build` produces
   `libsketch3d.so` per ABI. wry's `build.rs` also generates the Kotlin bridge
   (`WryActivity.kt`, `Rust.kt`, `RustWebView*.kt`, `Ipc.kt`) into
   `app/src/main/kotlin/com/notebysebas/sketch3d/`.
3. **Gradle** — `:app:assembleRelease` → `dist/Sketch3D-v4.3-release.apk`.

Output: `android/dist/Sketch3D-v4.3-release.apk`.

## Export bridge (why the web app needed a patch)

In a WebView `<a download>` does nothing, so `index.html` now routes every
export through `saveBlob()`:

```js
saveBlob(name, blob, mime)
  ├─ window.AndroidBridge.saveToDownloads(...)  → Kotlin → MediaStore/Downloads
  └─ <a download>                                → normal browsers
```

The web build is unchanged: the bridge is feature-detected, so the browser
path is still used on the web.

## Release signing

`assembleRelease` falls back to the debug key so the APK is always
installable. For a real release drop these two files in `android/keystore/`:

```
android/keystore/sketch3d-release.jks
android/keystore/keystore.properties
```

```properties
storePassword=...
keyAlias=sketch3d
keyPassword=...
```

They are git-ignored. Generate a keystore with:

```powershell
keytool -genkeypair -v -keystore android\keystore\sketch3d-release.jks \
  -alias sketch3d -keyalg RSA -keysize 2048 -validity 10000
```

## Publishing

Binaries do not belong in the git history — upload the APK as a release asset:

```powershell
gh release create v4.3-android .\dist\Sketch3D-v4.3-release.apk `
  --title "Sketch3D v4.3 (Android)" --notes "Rust/wry shell, offline, exports to Downloads"
```

`.github/workflows/android-apk.yml` does this automatically on every `v*` tag
and also publishes the APK as a workflow artifact on each push.

## Debugging

* `chrome://inspect/#devices` in a desktop Chrome (the release build enables the
  wry `devtools` feature).
* `adb logcat -s sketch3d` for the Rust logs.
* `adb shell dumpsys package com.notebysebas.sketch3d | findstr version` to check
  the installed build.
